# OpenVPN directive policy

MacVPN starts `openvpn` as root. Every directive in an OpenVPN config is sorted into one of three tiers before the config is saved, and again by the root layer (`mvpn validate`, built into the `mvpn` root helper) before every connection. The single source of the rules is `OpenVPNValidator` in `crates/core/src/validators/openvpn.rs` (`OpenVPNValidator::tier`); this page explains the classification. It was reviewed against the OpenVPN 2.6/2.7 manual (`man openvpn`, Homebrew OpenVPN 2.7.8).

[Magyar összefoglaló](#magyar-összefoglaló)

| Tier | Meaning | In the editor / import | At connect time (root) |
|---|---|---|---|
| **SAFE** | Allowed. The arguments are checked against a per-directive table (`argument_specs`). | Saved normally. | Accepted. |
| **RISKY** | Cannot cross the root privilege boundary, but can change how the connection or the system behaves. **Every unknown directive** is RISKY too. | Listed in the yellow **Risky settings** panel with a short reason. Saving needs the checkbox **I acknowledge these settings and the security risks**. | Accepted only if the connection acknowledged that directive *by name* (`--accept-risky`). |
| **FORBIDDEN** | Runs commands or loads code, reads or writes arbitrary files as root, opens a control channel, or overrides what MacVPN itself sets. | Red error, cannot be saved. | Always rejected, even if the name is passed in `--accept-risky`. |

General rules that apply to every tier: the directive name must be `[A-Za-z0-9-]` starting with a letter or digit (an optional leading `--` is ignored; a bare `--` is an *Invalid directive*); no control characters anywhere; no backslash and no unterminated quote; external files are never read (key material must be in inline blocks such as `<ca>…</ca>`); inline blocks are allow-listed; `<connection>` blocks are allowed (the single-line form `connection` `<file>` is an *Invalid directive*: it would read a file) and may only contain the connection options listed in the manual (SAFE ones only); error messages never quote config content, only the directive name.

## The acknowledgement

- The acknowledgement is stored per connection in `meta.json` as `acknowledgedRiskyDirectives` (a sorted list of directive names; missing in older files = empty).
- Ticking the checkbox stores **exactly the current set** of risky directive names when you save. If you later add another risky directive (or a different unknown one), the box is unticked again and saving or connecting is blocked until you acknowledge the new set.
- Connecting with an unacknowledged risky directive fails with *Risky settings are not acknowledged: … Open the connection in MacVPN → Connections and tick the checkbox under Risky settings.*
- The app passes the names to the root layer: `mvpn up openvpn <id> --accept-risky group,user --lang en`. `mvpn` checks the value against `^[a-z0-9-]+(,[a-z0-9-]+)*$` and hands it unchanged to its validator (`mvpn validate openvpn <file> --accept-risky …`). Only RISKY names can be accepted; a FORBIDDEN name in the list has no effect. Without the flag, risky directives fail validation as root too. `--lang` stays the last argument, so an older root layer still parses it.
- Arguments of RISKY (and unknown) directives must not contain a leading `-`, `..`, a leading `~`, `file:`, a backslash or shell metacharacters (`` ` $ ; | & < > ``), and `/` only in an IP/CIDR value. In addition, `mvpn` starts `openvpn` inside the root-owned run directory, so relative paths in options processed before daemonizing resolve there (after daemonizing OpenVPN does `chdir("/")`). A `/` is accepted only in a value that parses as an IPv4/IPv6 CIDR (`10.0.0.0/24`, `fd00::/64`), so `./123`, `a/1` or `dead.beef/42` are rejected. RISKY directives are not allowed inside `<connection>`.
- Unknown names that look like a hook, a file or a control channel are FORBIDDEN instead of RISKY: names starting with `management`, `pkcs11`, `plugin`, `script`, or ending in `-verify`, `-up`, `-down`, `-connect`, `-disconnect`, `-script`, `-dir`, `-file`, `-persist`, `-path`, `-exec`, `-cmd`.

Also denied: `POSIXLY_CORRECT`, `TMOUT`, `PATH_LOCALE`, `GREP_OPTIONS`, `OPENSSL_MODULES`, `OPENSSL_ENGINES`. As defence in depth, the hook applies an **environment allowlist**: it reads only `script_type`, `dev`, `ifconfig_local` and `foreign_option_N` and consults nothing else of its environment, checks server-sent values against strict formats without evaluating them, and runs `networksetup` with an explicit minimal environment (fixed `PATH` and `LC_ALL`).

## RISKY

| Reason (shown in the panel) | Directives |
|---|---|
| Drops root privileges after start: reconnecting may fail, and DNS is restored only when MacVPN disconnects | `user`, `group` |
| OpenVPN will not configure the interface or the routes: the tunnel may carry no traffic | `route-noexec`, `ifconfig-noexec` |
| Changes when MacVPN's DNS hooks run | `up-restart`, `down-pre` |
| Makes this Mac accept incoming VPN connections (listens on the network as root) | `mode`, `server`, `server-bridge`, `server-ipv6`, `tls-server`, `client-to-client` |
| Server-side option, not meant for a client connection | `ifconfig-push-constraint`, `duplicate-cn`, `max-clients`, `max-routes-per-client`, `ccd-exclusive`, `client-nat`, `connect-freq`, `connect-freq-initial`, `hash-size`, `bcast-buffers`, `stale-routes-check`, `verify-client-cert`, `client-cert-not-required`, `username-as-common-name`, `override-username`, `auth-user-pass-optional`, `auth-gen-token`, `ifconfig-pool`, `ifconfig-pool-linear`, `ifconfig-ipv6-pool`, `ifconfig-push`, `ifconfig-ipv6-push`, `iroute`, `iroute-ipv6`, `push`, `push-reset`, `push-remove`, `disable`, `vlan-tagging`, `vlan-accept`, `vlan-pvid`, `tls-crypt-v2-max-age` |
| Weakens the security of the tunnel (deprecated or insecure mode) | `allow-deprecated-insecure-static-crypto`, `compat-mode`, `no-replay`, `no-iv`, `key-method` |
| Allows routing that can bypass or loop the tunnel | `allow-recursive-routing` |
| Not supported on macOS (Windows or Linux only) | `win-sys`, `service`, `cryptoapicert`, `allow-nonadmin`, `setcon`, `msg-channel`, `rdns-internal`, `dhcp-internal` |
| Normally sent by the server or used internally by OpenVPN, not set in a client config | `key-derivation`, `protocol-flags`, `peer-id`, `push-continuation`, `http-proxy-override` |
| Removed from OpenVPN: the connection will fail to start | `compat-names`, `no-name-remapping`, `mtu-dynamic` |
| Debugging option that deliberately disrupts the connection | `gremlin` |
| Standalone mode: OpenVPN prints information or exits instead of connecting | `help`, `version`, `show-adapters`, `show-ciphers`, `show-digests`, `show-engines`, `show-gateway`, `show-groups`, `show-net`, `show-net-up`, `show-tls`, `show-valid-subnets`, `show-curves`, `test-crypto`, `mktun`, `rmtun` |
| Unknown to MacVPN: its effect cannot be checked | any directive not in a table (with the argument restrictions above) |

**`user` / `group`.** OpenVPN drops root after the tunnel is set up. MacVPN's up hook (DNS) has already run as root, but afterwards: the down hook runs as the unprivileged user and cannot restore DNS (MacVPN's `mvpn down` restores it as root from the saved `dns-backup` when you disconnect, also after openvpn has exited); a restart after `ping-restart` or a network change cannot reopen the tun device or re-read the password files unless the config has `persist-tun` (and, before OpenVPN 2.7, `persist-key`). MacVPN does not add these automatically. If OpenVPN exits on its own (for example `ping-exit`), DNS stays on the VPN servers until MacVPN disconnects the connection. Note also that macOS has `nobody` and `nogroup`, but the manual recommends a dedicated user.

|---|---|---|
| Script hooks | `up`, `down`, `route-up`, `route-pre-down`, `ipchange`, `tls-verify`, `auth-user-pass-verify`, `client-connect`, `client-disconnect`, `client-crresponse`, `learn-address`, `dns-updown`, `iproute`, `script-security` (2, 3 or anything else) | Run commands as root. ## OpenVPN 2.7

MacVPN is tested against the Homebrew build of OpenVPN 2.7.8 (`/opt/homebrew/sbin/openvpn`). The 234 option names printed by `openvpn --help` are pinned in `Tests/Fixtures/openvpn/openvpn-2.7.8-help-options.txt`, and all 315 names the 2.7.8 parser accepts (`streq(p[0], "…")` in `src/openvpn/options.c`, including undocumented aliases) in `Tests/Fixtures/openvpn/openvpn-2.7.8-source-options.txt`; unit tests check that every one has an explicit tier (none falls through to "unknown") and is named on this page. Aliases found in the source: `parameter` = `echo` (FORBIDDEN), `udp-mtu` = `link-mtu` (SAFE), `ip-remote-hint` = `preresolve` (SAFE). Findings of the review:

- **New / changed in 2.6–2.7:** `dns` (all forms: `search-domains`, `server n address|resolve-domains|dnssec|transport|sni`, server id −128…127, `[v6]:port`) is SAFE: because MacVPN passes `--up`, OpenVPN hands `dns` options to MacVPN's hook as `dhcp-option` style foreign options and does not run the default `dns-updown` script. `dns-updown` itself is FORBIDDEN (runs a command). `disable-dco`, `force-tls-key-material-export`, `push-peer-info`, `allow-pull-fqdn`, `tun-mtu-max`, `max-packet-size`, `session-timeout`, `route-ipv6-gateway` and `ifconfig-ipv6 addr/bits [remote]` (remote now optional) are SAFE. `client-nat` is RISKY (a CCD/server-pushed option). `tls-export-cert` (writes certificates to a directory) stays FORBIDDEN.
- **Deprecated or removed, still accepted by MacVPN** (OpenVPN decides; it may warn or refuse): `comp-lzo` (all forms), `ncp-disable`, `ncp-ciphers`, `opt-verify`, `persist-key` (always on since 2.7), `prng`, `max-routes`, `windows-driver`, `ns-cert-type`, `tun-ipv6`, `secret` (static key mode needs `allow-deprecated-insecure-static-crypto`, which is RISKY).
- **Arguments accepted as 2.7 does:** `data-ciphers` colon lists with `?` (optional) entries in any case, `tls-groups` colon lists, all four `tls-cert-profile` values, all `verify-x509-name` types, `remote host port proto` with every client `proto` (`udp`, `tcp`, `udp4`, `udp6`, `tcp-client`, `tcp4-client`, `tcp6-client`, …), every `redirect-gateway` flag (`def1`, `bypass-dhcp`, `bypass-dns`, `ipv6`, `!ipv4`, `local`, `autolocal`, `block-local`), every `dhcp-option` type (`DNS`, `DNS6`, `DOMAIN`, `DOMAIN-SEARCH`, `ADAPTER_DOMAIN_SUFFIX`, `NTP`, `WINS`, `NBS`, `NBT`, `NBDD`, `DISABLE-NBT`, `PROXY_*` with URL values), `route` with `net_gateway` / `vpn_gateway` / `remote_host` / an address and a metric, and `auth` / `cipher` names in any case, including legacy `BF-CBC` and `AES-128-CBC`.

## Management interface and MFA

MacVPN uses the OpenVPN management interface internally for multi-factor authentication (static and dynamic challenge, `CR_TEXT`, web / SAML / push sign-in). Every `management*` directive stays **FORBIDDEN** in configs, with or without acknowledgement; only `mvpn` adds the options, after `--config`, so they override anything a config could say:

```
--management /var/run/macvpn/<id>/mgmt.sock unix --management-client-user root
--management-hold --management-query-passwords
--auth-retry interact --setenv IV_SSO openurl,webauth,crtext
[--auth-user-pass]          (bare, only when a username/password is stored)
```

- **Socket.** A unix socket in the root-owned `0700` run directory; `--management-client-user root` makes OpenVPN refuse any other peer as well. No TCP port, no password file.
- **Hold.** OpenVPN waits for `hold release` at start and after every restart, so the helper is connected before anything happens.
- **Credentials.** `--management-query-passwords` with a bare `--auth-user-pass` makes OpenVPN ask the management interface for the username and password. A file given to `--auth-user-pass` cannot be used: with a file OpenVPN reads the dynamic-challenge (`CRV1`) and static-challenge responses from the console, which a daemon does not have (OpenVPN 2.7 `get_user_pass_cr` in `misc.c`). The bare option also overrides an inline `<auth-user-pass>` block. The private key password still comes from `--askpass <file>`.
- **`--auth-retry interact`** is required for the dynamic challenge: the server's `AUTH_FAILED,CRV1:…` restarts the connection and OpenVPN asks for the credentials again. On a final failure the helper stops OpenVPN, so a wrong password is not retried in a loop. `AUTH_FAILED,SESSION:` (expired auth-token) and `AUTH_FAILED,TEMP` (temporary server failure) are not final, in the helper and in `mvpn up`.
- **Credentials stay in root memory for the session.** The helper keeps the username and password in its memory (it is a root process) for the whole connection, so reconnects work even with `auth-nocache`. The raw file contents it reads, and the credentials when the session ends, are zeroed in memory (`zeroize`).
- **`IV_SSO`** tells the server that the client handles `openurl`, `webauth` and `crtext` pending authentication (it is always pushed, independent of `push-peer-info`). The DNS hook ignores it, like every variable outside its allowlist.
- **The helper** `mvpn mgmt-bridge` (the `mgmt-bridge` subcommand of the root binary `/usr/local/libexec/macvpn/mvpn`, installed with hash verification; process lists show it as `mvpn-mgmt`, the name it is started under) is the only client. It sends only these commands: `state on`, `hold release`, `username "Auth" …`, `password "Auth" …`, `cr-response <base64>`. There is no generic passthrough, and nothing from the user or the server is copied into a command except the quoted, escaped credential or response value (no line breaks or control characters, at most 255 bytes). It reads `>HOLD`, `>PASSWORD`, `>INFOMSG` (`OPEN_URL`, `WEB_AUTH`, `CR_TEXT`), `>STATE` (`AUTH_PENDING`, `CONNECTED`) and `>FATAL`, and ignores everything else (including `>ECHO` and `>PASSWORD:Auth-Token`). Lines over 4096 bytes are dropped, and every command line it builds is shorter than 1024 bytes (OpenVPN would run the bytes past 1024 as a new command). Challenge texts are cleaned of control and Unicode format characters (bidi, zero-width) and cut to 200 characters. A sign-in URL is kept only if it is `https://` with an ASCII host (letters, digits and hyphens, no trailing dot; punycode is not decoded), an IPv4 address or an `[IPv6]` literal, and no `%` or `@` in the authority. The host is shown and logged lowercase in this ASCII form. The total wait in one authentication round is capped at 420 s, however often the server repeats the request; after that the helper stops OpenVPN, also on a reconnect when the app is not watching.
- **What the user side sees.** The helper writes `/var/run/macvpn-ui/<id>.json` (owned by you, `0600`, in a root-owned `755` directory, written atomically and symlink-safe): the challenge text, the echo flag, the `https` URL, the state and the deadline. Never a password, code or token. Answers go back through `sudo mvpn respond openvpn <id>` (stdin `kind=crv1|static|webauth-ack|cancel`, `response=<value>`, at most 256 bytes, no control characters) into a root-only file the helper reads and deletes.
- **Log.** OpenVPN 2.7 logs `MANAGEMENT: CMD 'cr-response <b64>'` (and at verb 4 or more `SENT CONTROL …: 'CR_RESPONSE,<b64>'`). These lines, and every `MANAGEMENT: CMD '…'` line except `state`, `hold` and `version`, are dropped on every copy from `openvpn.log` to the connection log or into an error message.
- **Connected state.** The root-only `openvpn.log` (`Initialization Sequence Completed`, anchored, `ECHO` lines ignored) stays the only source of truth for "connected". The management `>STATE:…,CONNECTED` is used only to clear the authentication state: the log check is already hardened and also covers connections started before the root layer had a management interface.

## MikroTik RouterOS

Configs exported by RouterOS (`/interface ovpn-server server export-client-config` in v7) and the classic client configs from the MikroTik wiki for RouterOS v6 import with **no acknowledgement and no errors**. Fixtures: `Tests/Fixtures/mikrotik/` (v7 UDP, v7 TCP with `tls-auth`, v7 with `tls-crypt` and `data-ciphers`, a wiki config with many optional lines, and the v6 wiki config with separate files); they are checked by the unit tests and, as root, by `scripts/test-root.sh`.

- Every line they use is SAFE: `client`, `dev tun`, `proto tcp-client|udp|udp4`, `remote host [port] [proto]`, `port`, `nobind`, `float`, `persist-key`, `persist-tun`, `tls-client`, `pull`, `remote-cert-tls server`, `ns-cert-type server`, `verify-x509-name`, `cipher` (e.g. `AES-256-CBC`, `aes-128-cbc`), `data-ciphers`, `data-ciphers-fallback`, `auth SHA1|sha1|SHA256`, `tls-version-min`, `auth-user-pass`, `auth-nocache`, `auth-retry`, bare `askpass`, `redirect-gateway def1`, `route-nopull`, `route … vpn_gateway|net_gateway`, `route-delay`, `route-method exe`, `dhcp-option`, `block-outside-dns`, `setenv opt block-outside-dns`, `tun-mtu 1500`, `mssfix 1450`, `topology subnet`, `keepalive`, `ping-timer-rem`, `reneg-sec 0`, `resolv-retry infinite`, `connect-retry`, `remote-random`, `explicit-exit-notify` (also with TCP: OpenVPN only warns), `comp-lzo no`, `script-security 1`, `verb`, `mute`, `key-direction`, and the `<ca>`, `<cert>`, `<key>`, `<tls-auth>`, `<tls-crypt>` blocks.
- **Encrypted keys.** RouterOS exports the client key encrypted with the export passphrase (`-----BEGIN ENCRYPTED PRIVATE KEY-----`, or `Proc-Type: 4,ENCRYPTED` in older versions). Both forms import; the import note asks you to enter the passphrase in **Private key password**.
- **Credential files.** Wiki configs often use `auth-user-pass auth.cfg` (or `secret`, `user.txt`) and sometimes `askpass pass.txt`. On import, if the file is inside the `.ovpn`'s folder (same confinement as key files, symbolic links resolved), at most 1 KB and in the expected form (exactly two lines for `auth-user-pass`, the first line for `askpass`, no control characters), MacVPN asks **Use the credentials from … for this connection?** (**Use** / **Ignore**); only after **Use** do its contents go to the connection's Keychain fields (**Username** / **Password**, **Private key password**). Either way the line becomes a bare `auth-user-pass` / `askpass`. The file is never copied into the config. Otherwise the line still becomes bare and the import note asks you to enter the credentials.

## PKCS#12 and private key passwords

- **Import.** `pkcs12 client.p12` is inlined like the other key files: the file must be inside the folder of the `.ovpn` file (symbolic links resolved), at most 1 MB, a regular file opened with `O_NOFOLLOW`, and DER PKCS#12 (an ASN.1 `SEQUENCE` followed by `INTEGER 3`). It becomes a `<pkcs12>` block with base64 split into 64-character lines; the OpenVPN manual (*INLINE FILE SUPPORT*) requires inline PKCS#12 to be base64. The file is not opened or imported into the Keychain.
- **Export.** `<pkcs12>` is private key material: **Export Without Keys** removes it.
- **Password.** The OpenVPN editor has a **Private key password** field (Keychain item `<uuid>.keypass`). It is used for a password-protected PKCS#12 and for an encrypted PEM key (`-----BEGIN ENCRYPTED PRIVATE KEY-----`, or a legacy `Proc-Type: 4,ENCRYPTED` key). The app sends it to `mvpn` on stdin as `keypass=…` (no line breaks or control characters allowed). `mvpn` writes it to `/var/run/macvpn/<id>/askpass` (root, 600, in the 700 run directory), adds `--askpass` after the config (so it overrides any `askpass` line), masks it in the log, and deletes it on disconnect and on every failed connection attempt.

## Magyar összefoglaló

A MacVPN az OpenVPN config minden direktíváját három szintbe sorolja (`OpenVPNValidator::tier`), mentéskor és – hitelesen – rootként, minden csatlakozás előtt:

- **SAFE (biztonságos):** engedett, argumentum-ellenőrzéssel (pl. `remap-usr1`, `setenv CONFIG_VERSION "2.0.4"`, `machine-readable-output`, `pull-filter`, `dns`, `persist-*`, `data-ciphers*`). A `setenv` bármely shell-névvel SAFE, kivéve a fenti tiltólistát (ezek az értékek a root DNS hookhoz, a `mvpn hook ovpn-dns`-hez jutnak; a hook ezen felül csak az engedélyezett változókat olvassa).
- **RISKY (kockázatos):** nem lépi át a root jogosultsági határt, de a kapcsolat vagy a rendszer viselkedését befolyásolja (pl. `user`, `group`, `route-noexec`, `ifconfig-noexec`, szerveroldali és Windows-only opciók), és **minden ismeretlen direktíva**. A szerkesztő sárga **Kockázatos beállítások** paneljén soronként rövid indoklással jelenik meg; mentéshez és csatlakozáshoz be kell jelölni: **Tudomásul veszem a beállításokat és a biztonsági kockázatokat**. A tudomásulvétel név szerinti, és pontosan a mentéskori halmazra szól: egy új kockázatos direktíva új tudomásulvételt kér. A root oldalon `--accept-risky` adja át.
- **FORBIDDEN (tiltott):** soha, tudomásulvétellel sem: script hookok, kódbetöltés (`plugin`, `pkcs11-*` a `pkcs11-id`-vel együtt), `config`, `cd`, `chroot` (a MacVPN hookjai és jelszófájljai utána nem érhetők el), napló és vezérlés (`log`, `syslog`, `echo`, `management*`, …), root fájl-hozzáférés, `[inline]` nélküli fájlhivatkozás (köztük `askpass <fájl>`), tiltólistás `setenv`.

**OpenVPN 2.7:** a telepített 2.7.8 `--help` mind a 234 opciója kifejezetten besorolt (rögzített lista: `Tests/Fixtures/openvpn/`); a `dns` minden formája SAFE, a `dns-updown` tiltott. A `script-security 0|1` SAFE (a MacVPN `--script-security 2`-je felülírja), a 2/3 tiltott.

**MikroTik RouterOS:** a RouterOS v7 exportja és a v6 wiki szerinti configok tudomásulvétel és hiba nélkül importálódnak. A titkosított kulcshoz az import jelzi, hogy a **Privát kulcs jelszava** mezőt ki kell tölteni; az `auth-user-pass auth.cfg` / `askpass pass.txt` fájl tartalma (a mappán belül, ≤ 1 KB) megerősítés után (**Használat** / **Mellőzés**) a Keychainbe kerül, a configba soha. A `parameter` az `echo` álneve, tiltott; a DNS hook (`mvpn hook ovpn-dns`) környezet-allowlistet használ.

**MFA:** a `management*` direktívák a configban továbbra is tiltottak; a management interfészt csak a `mvpn` adja hozzá a config után (`--management <futási könyvtár>/mgmt.sock unix --management-client-user root --management-hold --management-query-passwords --auth-retry interact --setenv IV_SSO openurl,webauth,crtext`, jelszó esetén puszta `--auth-user-pass`), és egyetlen kliense a root `mvpn` bináris `mgmt-bridge` alparancsa (a folyamatlistában `mvpn-mgmt`), rögzített parancslistával (`state on`, `hold release`, `username`/`password "Auth"`, `cr-response`). A `static-challenge` támogatott: az app csatlakozáskor bekéri a kódot.

**PKCS#12:** az import a `pkcs12 fájl.p12`-t base64 `<pkcs12>` blokká alakítja (a config mappáján belül, ≤ 1 MB). A jelszavas PKCS#12 és a titkosított PEM kulcs jelszava a **Privát kulcs jelszava** mezőbe kerül (Keychain); a `mvpn` `--askpass` fájlként (root 600) adja át, a naplóban maszkolva, bontáskor törölve.
