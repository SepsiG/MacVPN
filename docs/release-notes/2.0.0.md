# MacVPN and WinVPN 2.0.0 – release notes (draft)

The release workflow writes only the fixed installation and signing notes into the draft release (`.github/workflows/release.yml`). Before publishing 2.0.0, paste the text below (English, then Hungarian) above them in the draft's description. This is the joint release of MacVPN (macOS) and WinVPN (Windows); the repository variable `WINVPN_MSI_IN_RELEASE` must be `true` (see [RELEASING.md](../RELEASING.md#release-200)).

## English

### MacVPN 2.0.0 (macOS)

**New**

- **Appearance:** Settings → Appearance: Match System, Light or Dark, for the menu and every window.
- **Connection notifications:** when a connection connects, drops, is reconnected or fails, with the reason in plain words (it names only the connection); a click opens its Log tab. Settings → Connection Notifications turns them off.
- **Missing VPN tools:** a connection whose tool is not installed stays in the list, greyed, with "Not installed: <tool> – System Status"; New and import offer only the types that can be used.
- **Reconnect automatically** after sleep or a network loss, only on the same network and only when the VPN's own networks are not directly reachable there; a switch per connection.
- **VPN tools always up to date:** System Status offers Homebrew updates of the VPN tools, and MacVPN runs `brew update` once a day.

**Fixed**

- **DNS after disconnecting:** one DNS manager in the root layer keeps the original DNS settings on disk and restores them when the last connection that changed them goes down, also after a crash, a kill or a restart while connected. Several DNS-setting connections no longer leave each other's DNS behind. WireGuard's DNS is handled by MacVPN instead of `wg-quick`.
- **Log size:** a connection's log is capped at 5 MiB plus one older part while the connection runs (a long session across sleep could write tens of gigabytes); OpenVPN runs with `--mute 20`.
- **strongSwan (IKEv2):** the CA, certificates and keys in Homebrew's `etc/swanctl` folders are used at every connect, so certificate authentication works without `swanctl --load-creds` (F1); two IKEv2 connections at once no longer unload each other (F2).

**Upgrade notes**

- **The root layer goes from 8 to 9:** after the update, System Status shows **Update required**; click **Authorize** and enter your admin password once. Until then OpenVPN, WireGuard, IKEv2 and SSTP connections are greyed.
- **Once, if needed:** an older MacVPN could leave a VPN's DNS server set after a crash or a restart while connected. If websites do not open on your normal network with no VPN connected, open System Settings → Network → the service → Details… → DNS and remove the VPN's DNS servers.

### WinVPN 2.0.0 (Windows) – the first WinVPN that connects

**New**

- **OpenVPN and WireGuard** through the **WinVPN Service** that the installer adds (LocalSystem; each user's connections are their own and end at sign-out). OpenVPN Community (with the DCO and TAP-Windows6 drivers) is installed from System Status with winget or OpenVPN's official installer; wireguard-nt comes with WinVPN.
- **L2TP/IPsec, IKEv2 and SSTP** through Windows' own VPN client, from your own account, without an administrator for the normal case. WinVPN keeps their entries in its own phonebook (not in Settings → VPN); passwords are passed only when dialling.
- **Your Windows VPNs** (Settings → Network & internet → VPN) are listed as system VPNs with live state, and can be connected with WinVPN's stored secrets or Windows' own.
- **One-time codes, sign-in in the browser, credential prompts, debug mode and the live log** for every type, as in MacVPN.
- **Engines update without a new WinVPN:** System Status offers the newest OpenVPN Community and wireguard-nt as soon as they are published (checked daily); the Windows VPN client is updated by Windows Update.
- **WinVPN updates itself** from releases signed with the maintainer's offline key (an administrator confirms the installation).
- **HTTPS team catalogs**, **Remove WinVPN from This Account…** (a clean-up before uninstalling), and the 2.0 features above (appearance, notifications, missing engines, reconnect, log caps).

**Known limits on Windows**

- **Cisco IPsec cannot connect:** Windows has no client for IKEv1 with XAUTH. Cisco connections from a Mac stay (editable, in backups and catalogs) and **Make an L2TP/IPsec Copy** creates an L2TP/IPsec connection of the same server; New does not offer Cisco IPsec.
- **IKEv2 with a pre-shared key is not supported:** the Windows IKEv2 client signs in only with EAP-MSCHAPv2 or a computer certificate. Such configs are kept and shown greyed with the reason.
- **L2TP/IPsec to a server behind NAT** needs a one-time administrator step: **Allow L2TP Behind NAT…** in the error, then a Windows restart.
- SSTP cannot skip the certificate check ("No verification"); a company CA must be trusted in Windows (**Trust This CA in Windows…**, an administrator confirms). OpenVPN `cryptoapicert` is not supported; WireGuard `FwMark` / `Table` only `auto` / `off`.
- The ARM64 MSI is built and checked but not tested on ARM hardware.

**Installing**

- `WinVPN-2.0.0-x64.msi` (most PCs) or `WinVPN-2.0.0-arm64.msi`. The MSI is not Authenticode-signed: SmartScreen warns once (More info → Run anyway). An administrator installs it; it updates the 1.5.0 preview in place and keeps your data.

### Security fixes (both apps)

- **OpenVPN configuration check (also in MacVPN 1.5.0 and earlier):** OpenVPN reads a configuration line in 256-byte pieces, so a crafted 255-byte line inside an inline block (such as `<ca>`) could end the block early for OpenVPN and smuggle forbidden directives past MacVPN's check. Every configuration line is now limited to 255 bytes ("Line too long"). A nested `setenv opt` chain that could crash the app or the service is refused too. Update to 2.0.0, especially if you import configurations from others or use team catalogs.
- **macOS:** the DNS of a disconnected VPN is now restored reliably (also after a reboot or a crash), with size limits on server-pushed DNS lists; connection logs are capped at 5 MiB.
- **Windows:** the WinVPN Service runs only from an administrator-only `C:\Program Files\WinVPN`; downloaded WireGuard and OpenVPN components are checked against their publishers' pinned certificate authorities; a CA added with **Trust This CA in Windows…** is trusted only for server and client authentication, never for signing software.
- Release files carry GitHub build provenance, checked before they are signed.

### Reporting a problem

Open an issue at https://github.com/SepsiG/MacVPN/issues with the product and version (MacVPN or WinVPN; the version is at the bottom of the menu or the popover), the macOS version or the Windows build, the connection type, and what you did. Connect in debug mode (Option-click on macOS, Alt-click on Windows), then use **Save…** in the connection's Log tab and attach the log: passwords, PSKs, codes and private keys are never in it. Exception: an SSTP debug log on macOS contains the MS-CHAPv2 exchange, so send it only privately. Never post a backup, a config with keys, or a team key.

## Magyar

### MacVPN 2.0.0 (macOS)

**Új**

- **Megjelenés:** Beállítások → Megjelenés: Rendszer szerint, Világos vagy Sötét, a menüre és minden ablakra.
- **Kapcsolatértesítések:** ha egy kapcsolat csatlakozott, megszakadt, újracsatlakozott vagy sikertelen, közérthető okkal (csak a kapcsolatot nevezi meg); kattintásra a Napló füle nyílik meg. A Beállítások → Kapcsolatértesítések kikapcsolja őket.
- **Hiányzó VPN-eszközök:** ha egy kapcsolat eszköze nincs telepítve, a kapcsolat a listában marad, kiszürkítve, „Nincs telepítve: <eszköz> – Rendszerállapot” felirattal; az Új menü és az import csak a használható típusokat kínálja.
- **Automatikus újracsatlakozás** alvás vagy a hálózat elvesztése után, csak ugyanazon a hálózaton, és csak ha a VPN saját hálózatai ott nem érhetők el közvetlenül; kapcsolatonként kikapcsolható.
- **Mindig friss VPN-eszközök:** a Rendszerállapot felkínálja a VPN-eszközök Homebrew-frissítését, és a MacVPN naponta egyszer lefuttatja a `brew update`-et.

**Javítva**

- **DNS a bontás után:** a root réteg egyetlen DNS-kezelője lemezen tartja az eredeti DNS-beállításokat, és visszaállítja őket, amikor az utolsó, DNS-t módosító kapcsolat bont, akkor is, ha kapcsolat közben összeomlás, leállítás vagy újraindítás történt. Több DNS-t beállító kapcsolat már nem hagyja hátra egymás DNS-ét. A WireGuard DNS-ét a MacVPN kezeli a `wg-quick` helyett.
- **Naplóméret:** egy kapcsolat naplója futás közben is legfeljebb 5 MiB, plusz egy régebbi rész (egy alvásokon átívelő hosszú munkamenet korábban több tíz gigabájtot is írhatott); az OpenVPN `--mute 20`-szal fut.
- **strongSwan (IKEv2):** a Homebrew `etc/swanctl` mappáiban lévő CA, tanúsítványok és kulcsok minden csatlakozáskor betöltődnek, így a tanúsítványos hitelesítés `swanctl --load-creds` nélkül működik (F1); két egyszerre élő IKEv2-kapcsolat már nem tölti ki egymást (F2).

**Frissítési tudnivalók**

- **A root réteg 8-asról 9-esre vált:** a frissítés után a Rendszerállapot **Frissítés szükséges** sort mutat; kattints az **Engedélyezés** gombra, és add meg egyszer az admin jelszót. Addig az OpenVPN-, WireGuard-, IKEv2- és SSTP-kapcsolatok szürkék.
- **Egyszer, ha kell:** egy régebbi MacVPN kapcsolat közbeni összeomlás vagy újraindítás után beállítva hagyhatta egy VPN DNS-szerverét. Ha VPN nélkül a szokásos hálózatodon nem nyílnak meg a weboldalak, nyisd meg a Rendszerbeállítások → Hálózat → a szolgáltatás → Részletek… → DNS oldalt, és töröld a VPN DNS-szervereit.

### WinVPN 2.0.0 (Windows) – az első WinVPN, amely csatlakozni is tud

**Új**

- **OpenVPN és WireGuard** a telepítő által felvett **WinVPN szolgáltatáson** keresztül (LocalSystem; minden felhasználó kapcsolatai a sajátjai, és kijelentkezéskor bomlanak). Az OpenVPN Communityt (a DCO és a TAP-Windows6 illesztőprogrammal) a Rendszerállapot telepíti wingettel vagy az OpenVPN hivatalos telepítőjével; a wireguard-nt a WinVPN-nel érkezik.
- **L2TP/IPsec, IKEv2 és SSTP** a Windows saját VPN-kliensével, a saját fiókodból, a szokásos esetben rendszergazda nélkül. A bejegyzéseiket a WinVPN a saját telefonkönyvében tartja (nem a Gépház → VPN alatt); a jelszót csak tárcsázáskor adja át.
- **A Windows VPN-jeid** (Gépház → Hálózat és internet → VPN) rendszer VPN-ként, élő állapottal látszanak, és a WinVPN-ben tárolt vagy a Windows saját titkaival csatlakoztathatók.
- **Egyszer használatos kód, böngészős bejelentkezés, hitelesítőadat-bekérés, debug mód és élő napló** minden típusnál, mint a MacVPN-ben.
- **Motorfrissítés új WinVPN nélkül:** a Rendszerállapot a legújabb OpenVPN Communityt és wireguard-nt-t kínálja, amint megjelennek (naponta ellenőrzi); a Windows VPN-kliensét a Windows Update frissíti.
- **A WinVPN frissíti magát** a fejlesztő offline kulcsával aláírt kiadásokból (a telepítést egy rendszergazda erősíti meg).
- **HTTPS-es csapatkatalógusok**, **WinVPN eltávolítása erről a fiókról…** (rendbetétel az eltávolítás előtt), és a fenti 2.0-s funkciók (megjelenés, értesítések, hiányzó motorok, újracsatlakozás, naplókorlát).

**Ismert korlátok Windowson**

- **A Cisco IPsec nem csatlakozik:** a Windowsban nincs IKEv1 XAUTH kliens. A Macről jött Cisco kapcsolatok megmaradnak (szerkeszthetők, benne vannak a mentésekben és a katalógusokban), és az **L2TP/IPsec másolat készítése** ugyanarra a szerverre L2TP/IPsec kapcsolatot készít; az Új menü nem kínál Cisco IPsec-et.
- **Az előre megosztott kulcsos IKEv2 nem támogatott:** a Windows IKEv2-kliense csak EAP-MSCHAPv2-vel vagy számítógép-tanúsítvánnyal jelentkezik be. Az ilyen configok megmaradnak, és az okkal együtt szürkén látszanak.
- **NAT mögötti szerverhez az L2TP/IPsec** egyszeri rendszergazdai lépést kér: **L2TP engedélyezése NAT mögött…** a hibaüzenetben, utána a Windows újraindítása.
- Az SSTP nem hagyhatja ki a tanúsítvány ellenőrzését („Nincs ellenőrzés”); egy céges CA-ban a Windowsnak meg kell bíznia (**A CA megbízhatóvá tétele a Windowsban…**, egy rendszergazda megerősíti). Az OpenVPN `cryptoapicert` nem támogatott; a WireGuard `FwMark` / `Table` csak `auto` / `off`.
- Az ARM64 MSI elkészül és ellenőrizzük, de ARM-hardveren még nem teszteltük.

**Telepítés**

- `WinVPN-2.0.0-x64.msi` (a legtöbb számítógéphez) vagy `WinVPN-2.0.0-arm64.msi`. Az MSI nincs Authenticode-dal aláírva: a SmartScreen egyszer figyelmeztet (További információ → Futtatás mindenképp). Rendszergazda telepíti; az 1.5.0-s előzetest helyben frissíti, és megtartja az adataidat.

### Biztonsági javítások (mindkét app)

- **OpenVPN-konfiguráció ellenőrzése (a MacVPN 1.5.0-t és a korábbiakat is érinti):** az OpenVPN 256 bájtos darabokban olvassa a sorokat, így egy szándékosan 255 bájtos sor egy beágyazott blokkban (pl. `<ca>`) az OpenVPN számára idő előtt lezárhatta a blokkot, és tiltott direktívákat csempészhetett át a MacVPN ellenőrzésén. Mostantól minden sor legfeljebb 255 bájt („Túl hosszú sor”). Az appot vagy a szolgáltatást összeomlasztó, egymásba ágyazott `setenv opt` láncot is elutasítja. Frissíts 2.0.0-ra, főleg ha mástól kapott konfigurációt vagy csapatkatalógust használsz.
- **macOS:** a bontott VPN DNS-e megbízhatóan visszaáll (újraindítás vagy összeomlás után is), a szerver által küldött DNS-listák méretkorláttal; a kapcsolatnaplók legfeljebb 5 MiB-osak.
- **Windows:** a WinVPN szolgáltatás csak a rendszergazdák által írható `C:\Program Files\WinVPN`-ből fut; a letöltött WireGuard- és OpenVPN-összetevőket a kiadóik rögzített tanúsítványkiadóihoz ellenőrzi; a **CA megbízhatóvá tétele a Windowsban…** gombbal hozzáadott CA csak szerver- és kliens-hitelesítésre megbízható, programok aláírására soha.
- A kiadás fájljai GitHub-eredetigazolást (build provenance) kapnak, amit aláírás előtt ellenőrzünk.

### Hibabejelentés

Nyiss egy issue-t a https://github.com/SepsiG/MacVPN/issues oldalon a termékkel és a verzióval (MacVPN vagy WinVPN; a verzió a menü vagy a popover alján), a macOS-verzióval vagy a Windows build számával, a kapcsolat típusával és azzal, mit csináltál. Csatlakozz debug módban (macOS-en Option+kattintás, Windowson Alt+kattintás), majd a kapcsolat Napló fülén a **Mentés…** gombbal mentsd el és csatold a naplót: jelszó, PSK, kód és privát kulcs sosem kerül bele. Kivétel: macOS-en az SSTP debug naplója tartalmazza az MS-CHAPv2 cserét, ezért azt csak privát csatornán küldd. Mentést, kulcsokat tartalmazó configot vagy csapatkulcsot soha ne tegyél közzé.
