# MacVPN and WinVPN 2.0.2 – release notes

Released 2026-10-28 (`v2.0.2`). A maintenance release on top of [2.0.1](2.0.1.md).

## English

### Both apps

- **Waiting for network.** When the Wi-Fi or the cable under a VPN goes away, the connection no longer claims to be connected. It shows **Waiting for network…** in the menu, the Connections window and the icon's tooltip, and the icon shows the half-filled shield.
  - Short drops of a few seconds are ignored.
  - When the network comes back, a tunnel that survived is connected again. A tunnel that dropped reconnects if **Reconnect Automatically** is on and you are back on the same network; otherwise it stays disconnected.
  - After 2 minutes without a network the connection is disconnected, so DNS and routes are restored. With **Reconnect Automatically** on, it reconnects once the same network is back.
  - A connection started through a control API lease is never reconnected, as before.
- **Connecting icon.** While a connection is still being set up, connecting or reconnecting, the icon shows a half-filled shield instead of the connected one. The tooltip names the state: "Connecting…", "Connected", "Waiting for authentication", "Waiting for network…".
- **Log tab: Clear Log…** empties a connection's log, including its older part, after a confirmation. It works while the connection is up; new lines keep coming. The log starts with a "Log cleared at <time>" line.
- **Log tab: time filter.** Next to Search: Any Time, Last 5 Minutes, Last 15 Minutes, Last Hour, Today, or a custom From–To range. It combines with the All / Commands / Errors filter and the text search, and Copy copies what is shown.
- The risk note for an OpenVPN configuration that drops root privileges no longer says DNS may stay changed: DNS is restored when the connection ends.

### WinVPN (Windows)

- Clearing a log goes through the WinVPN Service, which lets only the connection's own user clear it. With an older service the app says to update WinVPN first.

No root layer change on macOS (it stays 9).

## Magyar

### Mindkét app

- **Hálózatra vár.** Ha a VPN alól eltűnik a Wi-Fi vagy a kábel, a kapcsolat már nem mutatja magát csatlakozottnak. A menüben, a Kapcsolatok ablakban és az ikon súgójában **Hálózatra vár…** látszik, az ikon pedig a félig kitöltött pajzs.
  - A néhány másodperces kiesést figyelmen kívül hagyja.
  - Ha a hálózat visszajön, a túlélő alagút újra csatlakozott. A megszakadt alagút újracsatlakozik, ha be van kapcsolva az **Automatikus újracsatlakozás**, és ugyanarra a hálózatra kerültél vissza; különben bontva marad.
  - 2 perc hálózat nélkül után a kapcsolat bont, így a DNS és az útvonalak visszaállnak. Bekapcsolt **Automatikus újracsatlakozással** újracsatlakozik, amikor ugyanaz a hálózat visszajön.
  - A vezérlő API bérletével indított kapcsolatot továbbra sem hozza vissza.
- **Csatlakozás ikon.** Amíg egy kapcsolat még épül, csatlakozik vagy újracsatlakozik, az ikon a félig kitöltött pajzs, nem a csatlakozott. A súgó kiírja az állapotot: „Csatlakozás…”, „Csatlakozva”, „Hitelesítésre vár”, „Hálózatra vár…”.
- **Napló fül: Napló törlése…** megerősítés után kiüríti a kapcsolat naplóját, a régebbi részével együtt. Futó kapcsolatnál is működik, az új sorok tovább érkeznek. A napló egy „Napló törölve: <idő>” sorral kezdődik.
- **Napló fül: időszűrő.** A Keresés mellett: Bármikor, Utolsó 5 perc, Utolsó 15 perc, Utolsó óra, Ma, vagy Egyéni időszak (Ettől–Eddig). Együtt működik a Minden / Parancsok / Hibák szűrővel és a szöveges kereséssel, a Másolás azt másolja, ami látszik.
- A root jogot elhagyó OpenVPN-konfiguráció kockázati megjegyzése már nem állítja, hogy a DNS beállítva maradhat: a kapcsolat végén a DNS visszaáll.

### WinVPN (Windows)

- A napló ürítése a WinVPN szolgáltatáson keresztül megy, amely csak a kapcsolat saját felhasználójának engedi. Régebbi szolgáltatásnál az app kéri, hogy előbb frissítsd a WinVPN-t.

A macOS-es root-réteg nem változik (marad a 9-es).
