# MacVPN and WinVPN 2.0.3 – release notes

Released 2026-10-29 (`v2.0.3`). A reliability release on top of [2.0.2](2.0.2.md): a connection that should be up stays up.

**macOS: the root layer changes (9 → 10).** After the update, System Status shows "Update required (9 → 10)"; click **Authorize** once and enter your admin password. Until you do, the root-based kinds are greyed out.

## English

### Both apps

- **Dead tunnels are detected.** A connection whose tunnel stops working while your network is fine no longer shows as connected.
  - **WireGuard:** judged by its handshakes. With PersistentKeepalive it is dead after about 3.5 minutes without a handshake. Without keepalive it is dead only when traffic gets no answer. An idle tunnel is never flagged.
  - **OpenVPN:** while it reconnects by itself the row shows **Reconnecting…** and the icon the half-filled shield. If it is not back within 2 minutes, it counts as dead.
  - A dead connection is disconnected cleanly, so DNS and routes are restored, and you get a notice. With **Reconnect Automatically** on, it is reconnected; otherwise the row shows **Not responding**.
- **Network switch.** After you move to another Wi-Fi, a cable or a hotspot, a connection that was up is checked within about 10 seconds. A tunnel that still works is left alone. A dead one is reconnected on the new network if **Reconnect Automatically** is on. The office rule is unchanged: where the VPN's own networks are directly reachable, the connection is disconnected with a notice. After sleep, a connection is still reconnected only on the same network.
- **Reconnect after any drop.** With **Reconnect Automatically** on, a connection now also comes back after its engine crashes, the server ends the session, or the macOS root layer or the WinVPN Service restarts, as long as a network is present. A wrong password or a certificate error is never retried.
- **Slow retries.** When the quick attempts fail, the connection is tried again every 5 minutes for up to an hour. The row shows **Retrying in N min**. You get one notice when this starts and one when it ends. Connecting or disconnecting it yourself stops the retries.
- **App restarts.** Connections that are already up when the app starts are watched and reconnected like any other.
- **Control API leases.** A connection a lease started is still recognised as the lease's after the app restarts, so it is never reconnected automatically.

### MacVPN (macOS)

- An IKEv2 configuration without `dpd_delay` gets dead peer detection (`dpd_delay = 30s`). A configuration that sets its own value keeps it.

## Magyar

**macOS: a root-réteg változik (9 → 10).** A frissítés után a Rendszerállapot ezt mutatja: „Frissítés szükséges (9 → 10)”. Kattints egyszer az **Engedélyezés** gombra, és add meg az admin jelszót. Addig a root-réteget használó kapcsolattípusok szürkék.

### Mindkét app

- **Felismeri a halott alagutat.** Ha az alagút leáll, miközben a hálózatod rendben van, a kapcsolat már nem mutatja magát csatlakozottnak.
  - **WireGuard:** a handshake-ek alapján dönt. PersistentKeepalive mellett kb. 3,5 perc handshake nélkül halott. Keepalive nélkül csak akkor, ha a forgalomra nem jön válasz. A tétlen alagutat soha nem jelöli meg.
  - **OpenVPN:** amíg magától újracsatlakozik, a sorban **Újracsatlakozás…** látszik, az ikon a félig kitöltött pajzs. Ha 2 percen belül nem jön vissza, halottnak számít.
  - A halott kapcsolatot tisztán bontja, így a DNS és az útvonalak visszaállnak, és értesítést kapsz. Bekapcsolt **Automatikus újracsatlakozással** újracsatlakozik, különben a sorban **Nem válaszol** látszik.
- **Hálózatváltás.** Ha másik Wi-Fi-re, kábelre vagy hotspotra váltasz, a futó kapcsolatot kb. 10 másodpercen belül ellenőrzi. A működő alagúthoz nem nyúl. A halottat az új hálózaton újracsatlakoztatja, ha be van kapcsolva az **Automatikus újracsatlakozás**. Az irodai szabály nem változik: ahol a VPN saját hálózatai közvetlenül elérhetők, ott bont és szól. Alvás után továbbra is csak ugyanazon a hálózaton csatlakozik újra.
- **Újracsatlakozás minden megszakadás után.** Bekapcsolt **Automatikus újracsatlakozással** a kapcsolat akkor is visszajön, ha a VPN-program összeomlik, a szerver bontja a munkamenetet, vagy újraindul a macOS-es root-réteg, illetve a WinVPN szolgáltatás, feltéve, hogy van hálózat. Rossz jelszónál és tanúsítványhibánál nincs újrapróbálás.
- **Lassú újrapróbálás.** Ha a gyors próbálkozások nem sikerülnek, egy órán át 5 percenként újra próbálja. A sorban **Újrapróbálás N perc múlva** látszik. Egy értesítést kapsz, amikor elkezdi, és egyet, amikor abbahagyja. Ha magad csatlakoztatod vagy bontod a kapcsolatot, az újrapróbálás leáll.
- **Az app újraindítása.** Az app indulásakor már futó kapcsolatokat is figyeli, és ugyanúgy újracsatlakoztatja, mint a többit.
- **Vezérlő API bérletek.** A bérlettel indított kapcsolatot az app újraindítása után is a bérlethez tartozónak ismeri fel, így soha nem csatlakoztatja újra magától.

### MacVPN (macOS)

- A `dpd_delay` nélküli IKEv2-konfiguráció halott társ felismerést kap (`dpd_delay = 30s`). Ha a konfiguráció saját értéket ad meg, az marad.
